# Требования к сервису SubscriptionManager

Исходные требования — практическая работа № 2.

Анализ — ИИ-ассистент ChatGPT, решения принял студент.

Код и тесты — ИИ-ассистент Claude (получил отчёт по практике 2, ТЗ, исходные файлы, замечания и уточнение по архитектуре: ASP.NET Core, модульный монолит со слоями).

Полный разбор анализа — таблица 3 отчёта, API — [`API.md`](API.md).

## Исходные и итоговые требования

| ID | Исходное требование (практика 2) | Итог (реализовано) |
|---|---|---|
| FR-01 | Регистрация по email и паролю, email уникален | Email нормализуется (пробелы, нижний регистр), уникальный индекс, пароль 8–128 символов |
| FR-02 | Авторизация, выдача механизма для запросов | JWT Bearer, срок 60 минут |
| FR-03 | Получение и изменение разрешённых данных профиля | Меняются email и пароль (пароль — с подтверждением текущего) |
| FR-04 | Создание, получение, изменение, удаление подписки | Удаление мягкое (статус `Deleted`); period: Weekly/Monthly/Quarterly/Yearly; status: Active/Paused/Cancelled |
| FR-05 | Хранение платежей, история платежей | Добавлен `POST /api/subscriptions/{id}/payments`; статусы Pending/Succeeded/Failed |
| FR-06 | Расходы за период, агрегаты по подпискам | Только Succeeded, границы включительно, итоги по каждой валюте (валюты не складываются) |
| FR-07 | Нет доступа к чужим данным | Чужой ресурс — 403, несуществующий или удалённый — 404 |
| FR-08 | Проверка обязательных полей и значений | `name` 1–100, `amount` 0…1 000 000 000, `currency` 3 буквы, обязательные даты; ошибки — 422 |
| NFR-01 | Пароли только в виде хеша | PBKDF2-HMAC-SHA256, соль, 100 000 итераций |
| NFR-02 | Записи не теряются при сбоях | Сужено: запись через транзакции БД |
| NFR-03 | Повтор платежа не создаёт дубликат | Уникальный `externalId`: повтор — 200, чужая подписка — 409 |
| NFR-04 | Приемлемое время ответа | **Исключено из итогового ТЗ:** измерения не проводились, выходят за рамки работы |
| NFR-05 | Тестируемость бизнес-логики | Логика за интерфейсами; цель покрытия ≥90 % операторов и ≥80 % ветвей |
| NFR-06 | Документированные контракты API | `docs/API.md` и Swagger |

Коды ответа: 200/201, 400, 401, 403, 404, 409, 422, 500; единый формат ошибки (ProblemDetails с полем `errors`).

## Модель данных

User (id, email, passwordHash) 1—* Subscription (id, userId, name, amount, currency, period, startDate, status) 1—* Payment (id, subscriptionId, amount, currency, paymentDate, status, externalId). Платежи удалённой подписки сохраняются.

## Изменения относительно практики 2

- Не реализовано: правила переходов статусов, пагинация платежей, поле `provider`, проверка валюты по ISO 4217, ограничение числа попыток входа.
## 6. Известные ограничения

Перечислены в таблице 5 отчёта и в `docs/ARCHITECTURE.md`: нет ограничения числа попыток входа; `externalId` глобально уникален (раскрывает факт существования платежа); ключ JWT для разработки в `appsettings.json`; `EnsureCreated` вместо миграций; нет пагинации платежей; правила переходов статусов не вводились.
